# تسجيل الدخول في ماتعطل: رقم الهاتف الكويتي + رمز OTP حقيقي

اعتُمد هذا النظام في 23 نوفمبر 2026. الدخول والتسجيل **برقم الهاتف فقط** للجميع (عملاء وشركات وإدارة).

## كيف يعمل
1. المستخدم يكتب رقمه (+965، 8 أرقام) ← Supabase Auth يولّد رمزاً من 6 أرقام.
2. Supabase يستدعي دالة `send-sms` (Send SMS Hook موقّع) ← ترسل الرمز برسالة SMS عبر **kwtSMS**.
3. المستخدم يكتب الرمز ← رقم جديد = حساب جديد، ورقم مسجّل = نفس الحساب.
- **لا يوجد رمز ثابت أو وهمي.** التوليد والتحقق وانتهاء الصلاحية وحدود المحاولات كلها في Supabase Auth.
- **التصفح بدون حساب** متاح كما هو.
- **الحسابات القديمة المسجّلة بالإيميل:** «عندك حساب قديم بالإيميل؟» ← دخول مرة واحدة ← ربط الرقم برمز SMS ← نفس الحساب ونفس البيانات. بعدها الدخول بالرقم فقط. أي حساب مسجّل دخوله بدون رقم مؤكَّد يُحوَّل تلقائياً لصفحة ربط الرقم.

## المالك (Super Admin)
- رقم المالك المعتمد: مسجّل على حساب المالك الحالي (`app_settings.owner_user_id`، دور `admin`). **غير مؤكَّد** حتى يصل أول رمز SMS.
- أول دخول للمالك برقمه ← الرمز يؤكّد الرقم على **نفس الحساب** (نفس الصلاحيات والبيانات).
- الصلاحية مربوطة **بمعرّف الحساب** في قاعدة البيانات، لا بالرقم ولا بالواجهة:
  - `admin_set_role`: لا أحد يغيّر صلاحية المالك، ولا أحد يغيّر صلاحية نفسه، ومنح أو سحب «مدير» للمالك فقط.
  - RLS على كل الجداول تستخدم `is_admin()` / `is_staff()` / `is_owner()`.
  - Supabase Auth يمنع ربط نفس الرقم بحسابين، وتغيير رقم أي حساب يحتاج رمزاً يُرسل للرقم الجديد.
- لوحة الإدارة لا تظهر إلا لدور `admin`، والدور نفسه لا يقرأه إلا صاحبه أو الإدارة. رقم المالك غير موجود في كود التطبيق أو الموقع.
- **بعد نجاح أول رمز SMS للمالك:** يُطبَّق `supabase/proposals/owner_requires_verified_phone.sql`، فيصير الخادم يشترط رقماً مؤكَّداً برمز SMS لأي صلاحية إدارة، ورقم المالك المعتمد لصلاحية المالك.

## المطلوب من المالك (مرة واحدة)
### 1) kwtSMS
- التسجيل في https://www.kwtsms.com (مجاني، وفيه اسم مرسل تجريبي `KWT-SMS` للتجربة فقط).
- اسم مرسل تشغيلي (Transactional Sender ID): 14.950 د.ك مرة واحدة. يحتاج ترخيصاً كويتياً ساري المفعول، والبطاقة المدنية للمفوّض بالتوقيع، ونماذج موقّعة. المدة 5 أيام عمل أو أكثر.
- رصيد: 0.015 د.ك للرسالة، والحد الأدنى 1,000 رسالة (15 د.ك).
- من صفحة API في حساب kwtSMS: انسخ **API username** و **API password**.

### 2) أسرار الدالة في Supabase
Edge Functions ← Secrets:
| الاسم | القيمة |
|---|---|
| `KWTSMS_USERNAME` | API username |
| `KWTSMS_PASSWORD` | API password |
| `KWTSMS_SENDER` | اسم المرسل المعتمد حرفياً (أو `KWT-SMS` للتجربة) |
| `KWTSMS_TEST` | `1` للتجربة (لا تُرسل)، ثم `0` للإرسال الحقيقي |
| `SEND_SMS_HOOK_SECRET` | من الخطوة 3 |

دالة `send-sms` **منشورة** على Supabase من قبل. لا تحذفها.

### 3) إعدادات Supabase Auth
- Sign In / Providers ← **Phone**: فعّله، مع **Confirm phone**.
- **Email**: خلّه مفعّلاً، لأن الحسابات القديمة تحتاجه مرة واحدة لربط الرقم.
- Auth Hooks ← **Send SMS hook** ← HTTPS ← `https://xpnwhvbxordtsmnegvri.supabase.co/functions/v1/send-sms` ← انسخ الـ Secret إلى `SEND_SMS_HOOK_SECRET`.
- Rate Limits: راجع حد رسائل SMS بالساعة.

## الاختبار
1. `KWTSMS_TEST=1`: اطلب رمزاً من التطبيق ← تظهر الرسالة في Queue بحساب kwtSMS بدون إرسال.
2. `KWTSMS_TEST=0`: ادخل برقم المالك ← يصل SMS ← أدخل الرمز ← تفتح لوحة الإدارة.
3. بلّغ Claude لتطبيق `owner_requires_verified_phone.sql`، ثم أعد الدخول وتأكد أن لوحة الإدارة تعمل.
4. رقم آخر ← حساب عادي بدون لوحة إدارة.
5. رمز خاطئ عدة مرات ← يُرفض. طلب رمز جديد قبل 60 ثانية ← يُرفض.
