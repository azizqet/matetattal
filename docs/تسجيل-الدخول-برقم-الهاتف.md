# تسجيل الدخول في ماتعطل: رقم الهاتف الكويتي + رمز OTP حقيقي

اعتُمد هذا النظام في 23 نوفمبر 2026. الدخول والتسجيل **برقم الهاتف فقط** للجميع (عملاء وشركات وإدارة).

## كيف يعمل
1. المستخدم يكتب رقمه (+965، 8 أرقام) ← Supabase Auth يولّد رمزاً من 6 أرقام.
2. Supabase يستدعي دالة `send-sms` (Send SMS Hook موقّع) ← ترسل الرمز برسالة SMS عبر **kwtSMS**.
3. المستخدم يكتب الرمز ← رقم جديد = حساب جديد، ورقم مسجّل = نفس الحساب.
- **لا يوجد رمز ثابت أو وهمي.** التوليد والتحقق وانتهاء الصلاحية وحدود المحاولات كلها في Supabase Auth.
- **التصفح بدون حساب** متاح كما هو.
- **الحسابات القديمة المسجّلة بالإيميل:** «عندك حساب قديم بالإيميل؟» ← دخول مرة واحدة ← ربط الرقم برمز SMS ← نفس الحساب ونفس البيانات. بعدها الدخول بالرقم فقط. أي حساب مسجّل دخوله بدون رقم مؤكَّد يُحوَّل تلقائياً لصفحة ربط الرقم.

## المالك (Super Admin)
- رقم المالك المعتمد: مسجّل على حساب المالك الحالي (`app_settings.owner_user_id`، دور `admin`). **غير مؤكَّد** حتى يصل أول رمز SMS.
- أول دخول للمالك برقمه ← الرمز يؤكّد الرقم على **نفس الحساب** (نفس الصلاحيات والبيانات).
- الصلاحية مربوطة **بمعرّف الحساب** في قاعدة البيانات، لا بالرقم ولا بالواجهة:
  - `admin_set_role`: لا أحد يغيّر صلاحية المالك، ولا أحد يغيّر صلاحية نفسه، ومنح أو سحب «مدير» للمالك فقط.
  - RLS على كل الجداول تستخدم `is_admin()` / `is_staff()` / `is_owner()`.
  - Supabase Auth يمنع ربط نفس الرقم بحسابين، وتغيير رقم أي حساب يحتاج رمزاً يُرسل للرقم الجديد.
- لوحة الإدارة لا تظهر إلا لدور `admin`، والدور نفسه لا يقرأه إلا صاحبه أو الإدارة. رقم المالك غير موجود في كود التطبيق أو الموقع.
- **بعد نجاح أول رمز SMS للمالك:** يُطبَّق `supabase/proposals/owner_requires_verified_phone.sql`، فيصير الخادم يشترط رقماً مؤكَّداً برمز SMS لأي صلاحية إدارة، ورقم المالك المعتمد لصلاحية المالك.

## حدود الإرسال والتحقق
- **في التطبيق:** زر «أرسل الرمز مرة ثانية» يظهر بعد 60 ثانية.
- **دالة send-sms (قاعدة البيانات، لكل رقم):** رسالة كل 55 ثانية، و5 بالساعة، و10 باليوم. الرقم يُحفظ مُجزّأً (sha256)، والسجل يُحذف بعد يومين.
- **Supabase Auth:** 60 ثانية بين الطلبات، وحد المشروع للرسائل بالساعة، وحد محاولات التحقق، وانتهاء صلاحية الرمز.

## خطوات التفعيل من الآيفون (Safari فقط)
افتح الروابط في Safari. لوحات kwtSMS و Supabase تشتغل على الجوال، والأفضل تقلب الجوال بالعرض في صفحات الإعدادات.

### الخطوة 1: حساب kwtSMS وطلب API
1. افتح https://www.kwtsms.com وسجّل حساب جديد (مجاني).
2. من قائمة حسابك اطلب **API access**. عادةً ينقبل بنفس اليوم.
3. افتح صفحة **API** في حسابك وانسخ **API username** و **API password** في «الملاحظات» مؤقتاً.
   - هذي غير بيانات دخولك للموقع.
4. لا تفعّل **API lockdown (IP)**. خوادم Supabase ما لها عنوان IP ثابت.

### الخطوة 2: اسم المرسل والرصيد (مدفوع، بموافقتك)
1. اطلب **Transactional Sender ID**، مثلاً `MATATTAL`: إنجليزي، 11 حرف كحد أقصى، 14.950 د.ك مرة وحدة.
2. المطلوب: ترخيص كويتي، والبطاقة المدنية للموقّع، ونموذجين موقّعين بالقلم على ورق الشركة الرسمي. المدة 5 أيام عمل أو أكثر.
3. اشحن رصيد بـ KNET: 15 د.ك تكفي 1,000 رسالة.
4. **لين ينقبل الاسم:** تقدر تجرب بالاسم العام `KWT-SMS`، بس وصوله بطيء وما يوصل لكل الأرقام. هذا للتجربة فقط، لا تنشر التطبيق عليه.

### الخطوة 3: تفعيل الدخول بالرقم في Supabase
1. افتح https://supabase.com/dashboard وادخل، ثم افتح مشروع ماتعطل.
2. القائمة ☰ ← **Authentication** ← **Sign In / Providers** ← **Phone**:
   - فعّل **Enable Phone provider**.
   - فعّل **Confirm phone**.
   - اترك مزود الرسائل على الافتراضي. الإرسال الفعلي يصير من الـ Hook في الخطوة 4.
   - **SMS OTP Expiry:** `300`. **SMS OTP Length:** `6`.
   - اضغط **Save**.
3. نفس الصفحة ← **Email**: خلّه مفعّل، لأن الحسابات القديمة تحتاجه مرة وحدة لربط الرقم.

### الخطوة 4: ربط kwtSMS عن طريق Send SMS Hook
1. Authentication ← **Auth Hooks** ← **Add hook** ← **Send SMS hook**.
2. **Hook type:** `HTTPS`.
3. **URL:** `https://xpnwhvbxordtsmnegvri.supabase.co/functions/v1/send-sms`
4. اضغط **Generate secret** وانسخ السر كامل. يبدأ بـ `v1,whsec_`.
5. فعّل الـ Hook واضغط **Create** أو **Save**.

### الخطوة 5: أسرار الدالة (Secrets)
1. القائمة ☰ ← **Edge Functions** ← **Secrets** (أو Project Settings ← Edge Functions).
2. أضف هذي الأسرار واحد واحد، والصقها **بدون مسافات**:

| Name | Value |
|---|---|
| `SEND_SMS_HOOK_SECRET` | السر من الخطوة 4 كامل، مع `v1,whsec_` |
| `KWTSMS_USERNAME` | API username |
| `KWTSMS_PASSWORD` | API password |
| `KWTSMS_SENDER` | `KWT-SMS` للتجربة، وبعدها اسمك المعتمد حرفياً (حساس لحالة الأحرف) |
| `KWTSMS_TEST` | `1` أولاً |

> هذي القيم مكانها Supabase بس. لا ترسلها في المحادثة، ولا تحطها في GitHub أو التطبيق.

### الخطوة 6: حدود Supabase
Authentication ← **Rate Limits** ← **Rate limit for sending SMS messages**: حطها مثلاً `30` بالساعة للمشروع كامل، واضغط **Save**.

### الخطوة 7: التجربة
1. **وضع التجربة** (`KWTSMS_TEST=1`): افتح التطبيق في Expo Go، اكتب رقمك، واضغط «متابعة».
   - في حساب kwtSMS ← **Queue** المفروض تطلع الرسالة بدون ما تنرسل.
   - التطبيق بيطلب الرمز، والرمز ما بيوصل. هذا طبيعي في هذا الوضع.
2. **الإرسال الحقيقي:** Edge Functions ← Secrets ← غيّر `KWTSMS_TEST` إلى `0`.
   - ادخل برقمك ← يوصلك SMS ← اكتب الرمز ← تفتح لوحة الإدارة.
3. **بلّغ Claude** حتى يطبّق `owner_requires_verified_phone.sql`.
4. **إذا ما وصل الرمز:** Edge Functions ← **send-sms** ← **Logs**. سطر `kwtsms send failed ERR...` يقولك السبب:
   - `ERR003`: اسم أو كلمة مرور API غلط، أو API ما انقبل للحين.
   - `ERR010` أو `ERR011`: ما فيه رصيد.
   - `ERR008`: اسم المرسل غير مسموح.
