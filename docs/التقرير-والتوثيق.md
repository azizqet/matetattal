## 2) قاعدة البيانات (Supabase — مشروع «ماتعطل»)

### ما وُجد عند الفحص
- 21 جدولاً مع RLS مفعّل: شركات، مناطق، خدمات، طلبات انضمام، اشتراكات، خطط، عروض، تقييمات، طلبات خدمة، شكاوى، إشعارات، إعلانات سوق.
- البيانات الحقيقية: **6 شركات ونش فعّالة**، و**25 طلب انضمام** (8 جديدة)، ومستخدم مدير واحد.

### النسخة الاحتياطية
قبل أي تعديل أُخذت نسخة كاملة داخل قاعدة البيانات في المخطط الخاص `backup_20261122`. هذا المخطط غير مكشوف عبر الـ API ومقفل بالكامل. يحتوي على:
كل الجداول المهمة + كل السياسات (policies) + تعريفات كل الدوال + فهرس ملفات التخزين.

> لم تُحذف أي بيانات أو جداول أو سياسات قائمة. كل التعديلات إضافية.

### ثغرة أمنية حرجة تم اكتشافها وإصلاحها ⚠️
دالة الحماية `guard_company_update` كانت من نوع `SECURITY DEFINER`، فكانت تعتبر كل مستخدم هو «النظام». النتيجة: **أي صاحب شركة كان يستطيع اعتماد شركته وتمديد اشتراكه مجاناً لأي مدة**. تم الإصلاح في
`20261122101000_fix_definer_current_user.sql`، والاختبار الآلي يتحقق من ذلك (T42–T45).

### التحسينات المضافة
| الملف | المحتوى |

| `20261122100000_app_v3_hardening_billing.sql` | سحب صلاحيات غير لازمة، منع استدعاء دوال داخلية من الخارج، حد للطلبات المتكررة (3 طلبات انضمام للرقم يومياً)، حماية التقييمات (لا تقييم ذاتي ولا نقل التقييم)، ترقية دور المستخدم إلى «شركة» تلقائياً، جدول `app_settings`، جدول `payments`، دالة `request_subscription`، دالة `admin_activate_subscription`، دالة `admin_find_user`، و13 فهرساً للأداء |

### دورة حياة الشركة والاشتراك
```
تسجيل حساب شركة → إنشاء الشركة (pending، مخفية)
  → اختيار خطة + كود خصم → request_subscription (اشتراك pending بالمبلغ المحسوب)
  → الدفع (حالياً يدوي عبر واتساب الإدارة)
  → المدير يضغط «تأكيد الدفع والتفعيل» → admin_activate_subscription
      → يُسجَّل الدفع في payments
      → الشركة تصبح approved وفعّالة وتمتد sub_end تلقائياً
      → إشعار لصاحب الشركة
```
طريق الانضمام القديم (`join_requests` بدون حساب) ما زال يعمل للموقع وللتطبيق.

### ربط بوابة دفع كويتية لاحقاً
البنية جاهزة: جدول `payments` فيه `provider` (myfatoorah / tap / upayments / knet) و`provider_ref` و`payment_url`. الخطوات عند اختيار البوابة:
1. إنشاء Edge Function `create-payment` تستدعي API البوابة بمفتاحها السري (يُحفظ في Supabase Secrets، **ليس في التطبيق**) وتعيد رابط الدفع.
2. إنشاء Edge Function `payment-webhook` تتحقق من توقيع البوابة ثم تستدعي `admin_activate_subscription(id, note, provider, ref)` بصلاحية service_role.
3. تغيير `payment_mode` إلى `gateway` من لوحة الإدارة ← الإعدادات.

### تشغيل اختبار الصلاحيات
الصق محتوى `supabase/tests/rls_test.sql` في SQL Editor. النتيجة الناجحة تظهر كرسالة خطأ نصها
`ALL_RLS_TESTS_PASSED (rolled back)`، وكل التغييرات تُلغى تلقائياً. **النتيجة الحالية: نجاح كل الاختبارات.**

## 3) تطبيق الجوال

### التقنيات
Expo SDK 58 · React Native 0.88 · TypeScript (strict) · Expo Router · TanStack Query · supabase-js · خط Tajawal · RTL إجباري (`forcesRTL`).

| البحث | بحث نصي يفهم العربية (ة/ه، أ/ا، التشكيل)، فلترة بالخدمة والمنطقة و24 ساعة، ترتيب بالمسافة أو التقييم |
| صفحة القسم | شركات القسم (تشمل الشركات التي تقدّم الخدمة كخدمة إضافية) |
| صفحة الشركة | اتصال، واتساب مع إرسال موقعك، طلب خدمة عبر التطبيق، الأسعار، المناطق، الصور، التقييمات، المفضلة، الإبلاغ |
| طلباتي | متابعة حالة الطلب (جديد ← مقبول ← في الطريق ← منجز) وإلغاؤه |
| حسابي | الدخول، الإشعارات، المفضلة، البيانات، لوحة الشركة، لوحة الإدارة، الدعم |
| الدخول/التسجيل | حساب عميل أو حساب شركة، واستعادة كلمة السر |
| لوحة شركتي | إنشاء وتعديل الشركة، الشعار، مناطق الخدمة، قائمة الأسعار، موقع الشركة، متاح/غير متاح، إحصائيات الزيارات والاتصالات، طلبات العملاء، الاشتراك وكود الخصم |
| لوحة الإدارة | إحصائيات، طلبات الانضمام (قبول/رفض)، الشركات (اعتماد، تمديد، إيقاف، تعليق، ربط بحساب)، الاشتراكات (تأكيد الدفع)، الخطط وأكواد الخصم وأقسام الخدمات، الإعدادات العامة |

### الأمان في التطبيق
- لا يحتوي التطبيق إلا على المفتاح العام (publishable). كل الصلاحيات مفروضة في قاعدة البيانات، فحتى لو عُدّل التطبيق لا يستطيع المستخدم تجاوزها.
- الجلسة محفوظة محلياً وتتجدد فقط والتطبيق في الواجهة.

## 5) المتبقي قبل النشر في المتاجر
**يحتاج تدخلك:**
1. **حساب Expo** (مجاني) وتنفيذ `eas init` و`eas build`، أو تزويدي برمز وصول (Access Token) لأنفّذها.
2. **Apple Developer Program** (99$ سنوياً) لنسخة iOS، و**Google Play Console** (25$ مرة واحدة) لنسخة Android.
3. **تفعيل «Leaked password protection»** من Supabase ← Authentication ← Settings.
4. **اختيار بوابة الدفع** (MyFatoorah أو Tap أو UPayments) وتوقيع العقد للحصول على مفاتيح API.
5. **سياسة الخصوصية وشروط الاستخدام** على رابط عام (Apple وGoogle تطلبانها). أستطيع كتابة مسودتها.
6. **أيقونة وشاشة بداية بهوية ماتعطل** (حالياً أيقونات Expo الافتراضية). أرسل الشعار بجودة عالية.
7. **إعداد رابط إعادة التوجيه** في Supabase Auth (Site URL / Redirect URLs) لروابط تفعيل البريد واستعادة كلمة السر.

**تحسينات مقترحة لاحقاً:**
- الإشعارات الفورية (Push) عبر `expo-notifications` (جدول `push_tokens` جاهز).
- خريطة تفاعلية داخل التطبيق.
- إضافة إحداثيات للشركات الحالية لتحسين ترتيب «الأقرب».
- تحويل سياسات RLS إلى صيغة `(select auth.uid())` لتحسين الأداء عند زيادة البيانات.
- قسم «السوق» (جداول listings موجودة) يمكن إضافته كتبويب.
